# mili’s ~~hedonistic~~ cookbook

A personal recipe-management web app — import recipes by link or write them by hand, store each one as a **uniform metric markdown file**, and browse them as a beautiful recipe book. Every recipe shows its **macros, glycemic index (GI), glycemic load (GL), inflammation score, nutrition score (Nutri-Score 2023), and a 1–10 nutrient-balance score (NRF9.3 nutrient density)**.

Built as a fully static [Astro](https://astro.build) site, deployed to GitHub Pages. Recipes are the source of truth — versioned markdown in `src/content/recipes/`.

> **Live site:** https://milenaveleva.github.io/recipes-archive/

## Tech stack

- **Astro 6** — content collections with Zod-typed frontmatter; near-zero JS, interactive islands only where needed.
- **Tailwind CSS v4** (`@tailwindcss/vite`) — "modern heirloom cookbook" design system (Fraunces / Newsreader / Hanken Grotesk, paper + terracotta palette).
- **GitHub Pages** via `withastro/action` — static hosting, no backend.
- _Planned (Phase 1):_ React islands (`@astrojs/react`) for the in-app authoring UI.

## Develop

```sh
npm install        # install dependencies
npm run dev        # local dev server (http://localhost:4321/recipes-archive)
npm run build      # production build to dist/
npm run preview    # preview the production build
npm test           # unit tests, the golden reference recipes and the score-reproducibility guard
node scripts/rescore-recipes.mjs   # regenerate every recipe's nutrition block
node scripts/validate-recipes.mjs  # ingredient-data validation gate (--json <path>; exit 1 on errors)
node scripts/score-diff.mjs        # report dial changes vs HEAD (--ref <rev>, --threshold <n>; exit 1 if it fails)
```

> This repo pins `vite` to a single version via `overrides` so Astro and the Tailwind/React plugins share one Vite instance — do not remove it without re-checking the build.

## How recipes are stored

Each recipe is one markdown file: rich YAML frontmatter (structured, metric ingredients + a precomputed nutrition/score block) plus prose method steps in the body. See [`src/content.config.ts`](src/content.config.ts) for the full schema and any file in `src/content/recipes/` for an example.

Ingredients are stored **raw** — the raw food record and its raw weight — each with an optional `cooking` method (`raw`, `boiled`, `steamed`, `baked`, `grilled`, `fried`, `blanched`, `microwaved`; absent = raw). Every score is computed on the cooked, as-eaten dish, by the ingredient-based recipe calculation with yield and retention factors (Reinivuo & Laitinen 2007): per ingredient, each nutrient total is multiplied by its retention factor for the food group × method (USDA Release 6 2007, with Bognár 2002 for the vitamins and trace minerals USDA does not tabulate), and the mass by the group's cooking yield (Bognár 2002, or a USDA raw/cooked water balance). Macros keep their full totals; Nutri-Score and the nutrient-balance score profile per 100 g of the summed cooked mass; the inflammation index reads the cooked composition per 100 kcal, so retention losses move it but the water change cancels; GI values stay as published (they are as-eaten values) over the retained available carbohydrate. Frying adds no fat-uptake term — the cooking fat is its own ingredient. See [`src/core/cooking.ts`](src/core/cooking.ts) and [`src/data/README.md`](src/data/README.md).

## Roadmap

- **Phase 0 (done)** — static recipe book: schema, index/detail/taxonomy pages, score medallions, GitHub Pages deploy.
- **Phase 1** — in-browser authoring at [`/add`](https://milenaveleva.github.io/recipes-archive/add): sign in with GitHub, paste a URL (fetched via a Cloudflare Worker CORS proxy) or fill a form → review each ingredient's USDA match → auto-convert to metric → compute macros → commit the markdown to the repo. The Worker (see [`worker/`](worker/)) also runs the GitHub sign-in token exchange; set its URL as `PUBLIC_IMPORT_PROXY` at build time. Anyone can sign in, but only repository collaborators can publish.
- **Phase 2 (done)** — every recipe is scored in-app: a carb-weighted composite **glycemic index/load** (GI values transcribed from Atkinson 2021), lowered by a capped correction for the protein eaten with the carbohydrate and banded per serving by course: a full meal (main course, soup, salad, breakfast) with whole-meal GL cut-offs (low < 20, medium 20–39, high ≥ 40), every other course with the classic single-portion cut-offs (low ≤ 10, medium 11–19, high ≥ 20), the general-foods **Nutri-Score 2023** grade, an **inflammatory-potential** estimate (our own composition-derived index — not the licensed DII, and distinct from Wang 2025's published Food Inflammation Index): the dish's pooled, cooked composition read per 100 kcal and scored on fibre, vitamins C and E, magnesium, marine omega-3, carotenoids and flavonoid subclasses against free sugars (classified per food by the WHO definition, so whole and dried fruit carry none and blended or juiced fruit some), chain-length-weighted saturated fat, industrial trans fat and sodium, each weighted by the strength of the RCT evidence for its direction, with dairy and soy matrix corrections and a capped aromatic credit for ginger, turmeric, garlic, onion, saffron, black pepper, thyme/oregano and rosemary (Shivappa 2014 effect scores, an extrapolation of diet-level evidence, not validated per food) — and a 1–10 **nutrient-balance score** (the NRF9.3 nutrient-density index per 100 kcal), and a NOVA **processing** band from the energy share of each NOVA group (Monteiro 2019): *highly processed* only when ultra-processed (NOVA 4) foods supply ≥ 30 % of the energy, otherwise *minimally processed* when whole foods and culinary ingredients (NOVA 1–2) supply ≥ 70 %, and *moderately processed* for the rest — including dishes built on processed (NOVA 3) foods such as canned legumes, cheese or bread, which are processed but not ultra-processed. Scores are precomputed at author time into the markdown and shown as medallions.
- **Phase 3 (done)** — discovery on the home page: a fuzzy search box (Fuse.js, over titles, descriptions, ingredients and method text) and faceted filter chips (category, course, cuisine, lists, difficulty, the glycemic-index band, the glycemic-load level judged for the recipe's course — meal cut-offs for a full meal, single-portion cut-offs otherwise, matching its dial — and the Nutri-Score, inflammation and nutrient-balance bands) filter the pre-rendered card grid live. Pure, client-side, no extra build step — only facets the collection actually uses appear.
- **Later** — shopping lists + kifli.hu purchasing.

## Disclaimer

Nutrition, glycemic, and inflammation figures are **estimates for guidance only** — not medical or dietary advice.
